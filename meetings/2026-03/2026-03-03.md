# Development Meeting Summary

**Date:** March 3, 2026

---

## Chain Status and Temporal Mesh

The infrastructure lead reported pushing a new version of the chain after identifying ordering issues with EVM transactions. The testnet is running three validators in a converged mesh with time agreement, showing a consensus offset of around 21 microseconds. Because all validators currently run on the same machine, a class of true time-synchronization tests cannot yet be performed, and the mesh detects the low inter-node distance and reduces the quality score accordingly. The quality indicator is described as a user-facing signal rather than a hard technical value, but it remains useful — validators that misbehave drop toward 50% and are eventually ejected. Block time has been stable for roughly three weeks, and the team considers the temporal commitment mechanism validated.

## Fee Redesign Around Timestamping

A significant change in this version removes the dedicated time RPC; all transactions are now timestamped and treated uniformly as temporal transactions, eliminating the earlier model where users purchased and spent separate time tokens. With the RPC removed, a new "race for timestamping" emerges: transactions enter a pool of untimestamped items, and the first validator to see a transaction timestamps it. Under simulated load (around 500 transactions per minute on the weak testnet), this pool began to grow, requiring a selection mechanism. The proposed solution favors higher-fee transactions for faster timestamping, preserving fee competition and an open market while letting the chain return to the standard substrate fee system. Higher fees yield earlier, more precise timestamps; under heavy load the difference could reach tens to a few hundred milliseconds. The updated code is merged to main and CI was repaired.

## Outstanding Work and EVM Hardening

A heavy documentation refactor is still required, and the containerized node deployment needs to be rebuilt or verified to simplify joining the network. The validator onboarding tab is expected to be broken in this version because it still references older code. The team also flagged a need to investigate EVM-specific extrinsics: an earlier discovery showed certain calls (such as sudo calls) bypassed the transaction pool, which was fixed so they are now timestamped, but the EVM path must be audited for any similar bypass, since an un-timestamped on-chain action would be a serious attack vector.

## Time Mesh Implementation and Court System

The team discussed having re-implemented the PTP-squared mesh protocol rather than relying on the third-party time hardware vendor's software, because deeper integration with the substrate code was needed for features like automatic flashing and mesh-state-driven blockchain actions. Multiple audits and AI-assisted comparison runs were performed; the protocol is well documented and carries no licensing restrictions, though the team acknowledges it is hard to quantify any performance loss relative to the original vendor implementation without access to that source. The vendor hardware remains fully usable. The discussion also covered the "court" system, currently the only mechanism preventing validators from censoring transactions. It is considered safe but adds roughly two to three seconds of reconciliation latency to transaction inclusion (though not to timestamping), meaning transactions take at least a few blocks to be included. The team noted this could potentially be tuned down before mainnet.

## Discussion: Timestamping, Incentives, and Attack Surface

A question explored whether transaction signing depends on validator hardware. The infrastructure lead clarified that block producers have no control over timestamping; any validator can timestamp by carrying the mesh time consensus and reading from its time card, which imposes a natural physical rate limit. The team discussed a potential spam vector where an attacker floods transactions to delay others' timestamping, with higher fees and a larger validator set acting as the mitigation at scale. It was noted that transaction throughput per validator could become a useful quality metric. A caveat was raised that there is currently no direct reward for timestamping transactions, though the network functions as long as any validator performs the work; designing an incentive remains an open question.

## Tooling and Compute

The team briefly discussed shared API access for AI coding tools, current token allowances, and experiments with running self-hosted models on cloud GPUs, which were found to be more affordable than expected. Access to higher-end GPU hardware was confirmed, with internal work ongoing on authentication so the team can log in and use it.
